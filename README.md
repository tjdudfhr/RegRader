# RegRader Pro — 적용법규 자동 구성 (베타)

**회사명만 넣으면** 무료 공공데이터에서 업종·사업장·근로자 수·공장을 찾아 회사 정보를 채우고,
적용 법령과 고시 후보를 **왜 해당하는지 근거와 함께** 직무별로 만들어 주는 도구. 돌리는 데 돈이 들지 않는다.

- 회사 찾기: 국민연금 가입 사업장 내역(업종·주소·가입자 수)과 전국등록공장현황(공장·산업단지·생산품)을 내 컴퓨터 안에서 검색한다.
  본사·공장·연구소 사업장을 한 회사로 묶고, 항목마다 근거와 출처를 붙인다.
- 인허가도 공공데이터로 확인한다: 대기 배출시설, 고압가스, 특정고압가스 사용신고, 집단급식소, 식품제조가공업, 물류창고, 비산먼지, 통신판매업, 폐수·소음진동·폐기물(일부 지자체).
- DART(OpenDART 공식 API, 무료 인증키)로 상장 여부·외부감사 대상·공시대상기업집단 소속, 표준산업분류, 자산총계(사업보고서·감사보고서),
  사업보고서 본문의 사실(수출·해외법인·연구소·하도급·배출권 할당 등)을 근거와 함께 자동으로 정한다. 사람이 고르지 않는다.
- 공개 자료가 없는 사실(설비·물질 등)은 엔진이 업종·규모로 추정하고, 근거를 'AI 판단 근거'에 보여 준다. 틀린 것만 고치면 된다.
- 법령마다 **이 회사가 지켜야 할 주요 의무를 조문과 함께** 보여 준다 (예: 근로기준법 제93조 취업규칙 작성·신고 — 상시 10명 이상). 근로자 수·인허가에 따라 해당하는 의무만 고른다.
- 직무는 안전·환경·인사노무·재무회계·공정거래·정보보호·지배구조·지식재산권·기타 9개다. 빠진 법령은 화면에서 직접 추가한다 (법제처에서 이름을 확인).
- 법령명은 국가법령정보센터 Open API로 실제 있는지 확인하고, 법령체계도를 따라 시행령·시행규칙과 연결된 행정규칙(고시·훈령·예규)까지 펼친다.
- 연결된 행정규칙은 회사 조건(키워드·사업장 지역·업종)에 맞는 것만 추천하고, 나머지는 '더 보기'로 둔다.

회사 고유 데이터는 쓰지 않는다. 규칙은 일반 법령 지식으로만 작성했다.

## 판정 체계 (핵심)

대한민국 현행 법률 전부(국가법령정보센터, 2026-10 기준 1,725건)를 회사마다 빠짐없이 넷 중 하나로 판정하고, 직무별로 나눈다.

- 기업에 자주 적용되는 법률 120개는 `kb/rules.json` 의 정밀 규칙(조건·주요 의무 조문까지)으로 판정한다.
- 나머지 법률은 `kb/universe.json` 이 한 건씩 분류한다.
  - 모든 회사 (23건, 예: 민법·상업등기법·공익신고자 보호법·예비군법)
  - 조건부 (314건): 업종·사실·규모 조건 (예: 은행법 → 은행, 직장어린이집 → 상시 500명 이상, 교통유발부담금 → 건물 소유)
  - 기업 대상이 아닌 법률: 국가·공공기관 조직법, 특정 기관 설립법, 개인 대상법, 특정 사건법, 특정 지역법, 진흥·지원법, 절차·처벌법, 특정 거래법, 특정 사업자·자격사 대상법.
    이 법률들은 '미적용'으로 판정하고 이유를 붙인다.
- 금융업 법령(은행법·보험업법·금융소비자보호법·금융사지배구조법·특정금융정보법 등)은 직무 '지배구조'에 둔다.
- 새 법률이 생기거나 이름이 바뀌면 `python3 -m engine.universe status` 와 자체 점검이 '분류 안 된 현행 법률'로 알려 준다.
  `kb/universe.json` 에 한 줄을 더하면 된다.

| 판정 | 뜻 | 함께 보여 주는 것 |
|---|---|---|
| 적용 | 확인된 사실(공공데이터·사업보고서·사용자 수정)로 적용 조건이 맞음 | 적용 근거, 주요 의무(조문) |
| 적용(추정) | 엔진이 '예'로 추정한 사실로 적용 (예: 300명 이상 제조사의 건설공사 발주) | 추정한 사실과 근거 — 틀리면 '아님'으로 뒤집음 |
| 미적용 | 적용 조건이 맞지 않음 (아니오로 추정한 경우 '추정' 표시) | 이유 (예: 상시근로자 30명 미만, 비상장, 수출입 해당 없음) |
| 확인 필요 | 근로자 수·지역을 전혀 모를 때만 (회사 찾기로 찾은 회사에는 없음) | 입력할 값 |

사람에게 묻지 않는다. 회사 사실은 다음 순서로 엔진이 정한다.

1. **OpenDART** (`.env` 의 `OPENDART_KEY`, 무료): 기업개황의 표준산업분류, 최근 사업보고서 원문(회사의 개요·사업의 내용·
   직원·계열회사·그 밖의 사항·상세표), 직원 현황 API. 수출 비중, 해외법인, 기업부설연구소, 하도급 거래, 배출권 할당 대상,
   유해화학물질·위험물, 기간제 인원 등을 근거 문장과 함께 확인한다 (`engine/opendart.py`).
   DART 웹사이트 보고서 화면은 robots.txt 가 자동 수집을 막으므로 쓰지 않는다.
2. **공공데이터**: 국민연금 업종·인원, 등록공장, 인허가(대기·폐수·소음·가스·집단급식소·통신판매 등), 상장·재무.
3. **사전 판단** (`kb/facts.json`): 위에서 확인되지 않은 사실은 likely 조건(업종·규모·다른 사실)이 맞으면 '예(추정)',
   아니면 '아니오(추정)'. 추정 사실에서 다시 추정할 수 있다 (건물 소유(추정) → 승강기·저수조 관리).
   경계 판단(review)은 공개 자료로 알 수 없고 중요한 법령이 갈리는 6가지 사실에만 두고, 화면에는 최대 5개만 보인다.
4. **업종 표** (`kb/industry_laws.json`): 국세청 업종코드 1,542개(국민연금 사업장 업종코드와 같은 체계) 전부를 4자리 묶음 307개와
   세부 업종으로 나눠, 업종마다 그 업종의 인허가 근거법·업종 규제법(308종)을 정해 두었다. 회사의 업종코드가 확인되면 이 표가
   업종 법규를 정하고(넓은 업종 조건은 쓰지 않음), 업종코드가 없거나 미분류인 회사만 업종 태그 조건으로 판정한다.
   `python3 -m engine.industry 552101` 로 업종 하나의 법규를 볼 수 있다. 출처: 국세청 경비율 고시 (`python3 -m engine.datasets download ntscode` 는 안내용, 원문은 국세청 고시 첨부 hwpx).
5. 업종은 인허가 단위로 나눈다 (숙박/음식점, 화장품/의약품, 항공기/선박, 영화·음악·공연·신문, 도축·유가공·사료·인삼,
   주류/담배, 택배·택시, 발전·송배전·가스·집단에너지, SI·클라우드·전자서명, 회계·법무·세무·특허·노무 법인 등).
   공시 표준산업분류가 있으면 국민연금 사업장별 신고 업종보다 우선한다.

- 규칙(`kb/rules.json`·`kb/universe.json`)은 법령이 어떤 사실·규모에서 적용되는지만 적는다. 판정 계산은 `engine/classify.py`.
- 법령마다 직무는 하나 (안전·환경·인사노무·재무회계·공정거래·정보보호·지배구조·지식재산권·기타).

### 자체 점검

```bash
python3 -m engine.selfcheck              # 구조 + 판정 불변식 + 회사 유형별 정답 (오프라인)
python3 -m engine.selfcheck --online     # + 현행 법률 목록을 새로 받아 분류표와 대조, 법령명·의무 조문 대조
python3 -m engine.selfcheck --search     # + 회사 찾기 검증 (상장사 전수·대형 회사·짧은 검색어)
python3 -m engine.universe status        # 현행 법률 중 분류 안 된 것·폐지된 것
```

- 구조: 법령마다 직무 하나, 규칙·사실 표·의무 표가 쓰는 사실이 입력 항목에 있음
- 판정 불변식: 모든 법령이 판정됨, 미적용엔 이유·추정엔 추정한 사실이 있음
- 현행 법률 전부 판정: 현행 법률 하나하나가 분류표에 있고 판정 규칙이 있음
- 회사 유형별 정답(`kb/archetypes.json`): 3명 사무실·12명 IT·40명 공장·80명 식품·200명 건설·1,000명 화학 상장·비상장 대기업 계열·근로자 수 모름,
  은행·생명보험·카드·금융지주·저축은행·증권
  — 반드시 적용·미적용일 법령과, 추정을 고치면 판정이 바뀌는지(예: 하도급 거래 추정 → '맞음'이면 적용, '아님'이면 미적용).
  근로자 수·지역을 아는 회사에 질문이 하나라도 나오면 실패
- 규칙·사실 표·의무를 고칠 때마다, 그리고 법령 개정을 반영할 때 돌린다. 새로 확인한 법적 판단은 `kb/archetypes.json` 에 정답으로 더한다.

## 범위

규칙은 회사가 체크하지 않아도 업종·규모·인허가로 적용한다 (예: 근로자 300명 이상 제조사 → 하도급법 필수, 수출입·기술보호·
에너지·온실가스 법령은 적용 확인). 행정규칙은 법령체계도에 연결된 것 중 기관 내부용·다른 업종·계열 범위 밖(`kb/admin_scope.json`)만
빼고 모두 후보로 둔다 (규칙 키워드가 맞는 것은 '추천', 나머지는 '관련'). `kb/universe.json` 이 판정하는 법률은 체계도에 기관 내부
규정이 많아서, 그 법률의 `adm` 낱말에 맞는 행정규칙만 붙인다.

업종은 국민연금 업종코드(앞 4자리·2자리)와 업종명, 거래소 상장법인목록 업종, 등록공장 생산품, 그리고 금융회사는 회사명
(금융지주·저축은행·카드·캐피탈·증권·자산운용·생명·화재 등)으로 정한다. 금융회사는 국민연금에 엉뚱한 업종으로 신고된 경우가 있다
(예: 신한카드 '기타 금융 투자업', 현대캐피탈 '방문판매원').

실제 회사가 관리하는 적용법규 목록과 비교하면 (공공데이터만으로 만든 초안, 사람이 고치지 않은 상태):
법령 계열 100% · 법령(시행령·시행규칙) 100% · 행정규칙 약 80% 포함. 빠지는 행정규칙은 다른 지역 고시와 기관 위원회 규정이 대부분이다.

## 실행

국내 IP에서 실행한다 (법제처 API가 해외 IP를 막는다). Python 3.9 이상, 설치할 패키지는 없다.

```bash
python3 server.py
```

브라우저에서 `http://127.0.0.1:8787` 을 연다. 오른쪽 위에 `공공데이터 ○○○○-○○ 기준`이 보이면 회사 찾기를 쓸 수 있다.
법제처 인증 아이디는 환경변수 `LAW_OC` 로 바꿀 수 있다.

### RegRader 로 보내기 (분기별 · 직무별 모니터링)

판정 결과 화면의 **RegRader로 보내기** 를 누르면 선택한 적용법규(법령 + 행정규칙)로 RegRader 데이터를 만들고,
RegRader 저장소에 **커밋된** 수집 스크립트(`refresh_laws.py` → 계열 · 행정규칙 개정 · 개정 분석)를 그대로 돌린다.
끝나면 `http://127.0.0.1:8787/rr/<회사>/` 에서 지금 RegRader 와 같은 화면(종합 · 분기별 · 직무별 · 적용법규 · 계열)으로 본다.

```bash
python3 -m engine.export_regrader 에코프로비엠            # 명령줄: 회사 찾기 → 판정 → 내보내기 → 수집
python3 -m engine.export_regrader 에코프로비엠 --no-run   # 적용법규 목록만
```

- 결과는 `out/regrader/<회사>/` (저장소에 넣지 않는다). 화면 파일은 `out/regrader/_site/` 하나를 같이 쓴다.
- 보낸 회사 목록은 `http://127.0.0.1:8787/rr/` . RegRader 사이트의 '기업별 적용법규' 탭이 이 화면으로 연결한다
  (다른 사이트가 이 서버의 데이터를 읽지 못하게 CORS 는 열지 않는다. 탭은 이 PC 의 화면으로 이동만 한다).
- RegRader 저장소의 `pro/` 에 같은 코드가 들어 있다 (git subtree, 원본은 비공개 저장소 `tjdudfhr/regrader-pro`).
  RegRader 쪽을 최신으로: `git subtree pull --prefix=pro https://github.com/tjdudfhr/regrader-pro.git main --squash`
  `pro/` 에서 실행하면 그 RegRader 저장소를 쓴다 (회사 찾기 자료 · `.env` 는 따로 준비).
- 진행 막대에 단계(올해 개정 목록 → 계열 묶기 → 행정규칙 개정 목록 → 개정문 분석)와 진행률이 보인다.
- 법제처 응답은 Pro 판정과 같은 저장소(`.cache/lawapi`)를 같이 쓴다 (`engine/rr_launch.py` 가 RegRader 스크립트를 고치지 않고 감싼다).
  Pro 가 판정하며 받은 법령체계도를 다시 받지 않고, 회사끼리도 같이 써서 첫 수집이 13분 → 1~3분으로 줄었다.
  날짜 범위 목록(올해 개정·행정규칙 개정)은 3시간, 나머지는 7일 동안 쓴다.
- RegRader 저장소 위치는 `REGRADER_REPO` (기본 `~/RegRader-autoupdate`). 수집에는 `requests` 가 있는 파이썬이 필요하다 (`REGRADER_PYTHON`).
- 회사 사본에서는 직무에 '기타'를 더하고, 대응 현황(Supabase 로그인)과 GitHub 법규 추가 요청은 끈다.
- 행정규칙 범위는 RegRader 의 회사 검토 목록 대신 Pro 판정(추천 · 관련 · 묶음)을 쓴다.

### 브라우저판 (RegRader 사이트 · 서버 없음)

https://tjdudfhr.github.io/RegRader/pro/ — 판정 엔진(engine/*.py)을 Pyodide(브라우저 파이썬)로 그대로 돌린다.
맥 서버판과 같은 엔진 · 같은 결과다 (8개 회사로 계열 · 상태 · 직무 · 행정규칙 ID 까지 일치 확인).

- 법제처 조회 대신 `lawpack.json` (판정에 나오는 법령 1,725개의 현행 정보 · 법령체계도 · 고시)
- 회사 찾기: 국민연금 가입자 30명 이상 법인 + 상장사 (약 4.9만 곳). 개인사업자는 넣지 않는다. 그 밖의 회사는 직접 입력
- RegRader로 보내기: 회사마다 수집하지 않고, **전체 법률 수집 결과**(현행 법률 전체를 적용법규로 둔 RegRader 수집)에서
  회사 적용법규 · 행정규칙만 골라 만든다 (`engine/rr_static.py`, 즉시). 회사 작업 폴더에서 실제로 수집한 것과
  적용법규 · 행정규칙 · 계열 배치가 같다 (`python3 -m engine.static_site check`)
- 결과는 방문자 브라우저(IndexedDB)에만 저장된다. 회사 RegRader 화면: `docs/pro/site/?company=<회사>`

자료는 맥에서 만들어 RegRader 저장소의 `pro-data` 브랜치(기록 없이 덮어쓰기)에 올린다 — RegRader `scripts/pro_publish.sh` 가 매일 07:00 갱신 뒤에 부른다.

```bash
python3 -m engine.static_site daily      # pack → universe → (30일마다 companies) → publish
python3 -m engine.static_site web ~/RegRader-autoupdate/docs/pro   # Pro 코드를 바꿨을 때 브라우저판 화면 다시 만들기
```

- 상장사 DART 조회는 한 곳씩 (동시에 부르면 OpenDART 가 막는다). 연속 10번 실패하면 멈추고 다음 갱신 때 이어서 (`dart_pass`)

## 회사 찾기 자료 준비

공공데이터를 내려받아 `data/raw/` 에 두고 색인을 만든다 (모두 무료, 이용허락 제한 없음). 원본과 색인은 git 에 올리지 않는다.

```bash
python3 -m engine.datasets download          # 전부 받기 (약 1.3GB, 통신판매업이 900MB)
python3 -m engine.datasets download air meal # 일부만
python3 -m engine.companydb build            # 색인 만들기 (data/companies.sqlite, 1분 안쪽)
python3 -m engine.companydb search 회사명     # 확인
```

| 이름 | 자료 | 제공 | 갱신 |
|---|---|---|---|
| `nps` | 국민연금 가입 사업장 내역 (업종·주소·가입자 수) | 공공데이터포털 | 매월 |
| `factory` | 전국등록공장현황 (공장·산업단지·생산품) | 공공데이터포털 | 매년 |
| `air` `gas` `sgas` `meal` `food` `warehouse` `dust` `ecommerce` | 대기 배출시설, 고압가스업, 특정고압가스 사용신고, 집단급식소, 식품제조가공업, 물류창고업, 비산먼지 발생사업, 통신판매업 | 행정안전부 지방행정 인허가 (file.localdata.go.kr) | 매일 |
| `water` `noise` `waste` | 폐수배출사업장, 소음·진동 배출시설, 폐기물 배출업체 | 공공데이터포털 표준데이터 (올린 지자체만) | 수시 |
| `listed` | 상장법인목록 (시장·종목코드·업종·주요제품·지역) | 한국거래소 KIND | 수시 |
| `fin` | 최근 사업보고서 재무상태표 일괄 (자산총계, 별도 우선) | 금융감독원 DART 재무정보 일괄다운로드 | 분기 |

목록은 `python3 -m engine.datasets list`. 새 자료를 받으면 `build` 를 다시 돌린다.

회사 찾기 순위는 이름 일치(같음 > 앞부분 > 포함)와 회사(법인) 하나하나의 규모(국민연금 가입자), 상장 여부로 정한다.
영문은 한글 읽기로 통일하고(LG전자 = 엘지전자, KT&G = 케이티앤지), 거래소 약칭은 색인할 때 등기 이름에 연결한다(신한지주 → 신한금융지주회사).
`python3 -m engine.searchcheck` 로 상장사 전수(스팩 제외)·대형 회사 500곳·짧은 검색어 30개를 검증한다
(기준: 상장사 3위 안 97%, 대형 회사 1위 97%, 짧은 검색어 전부 — 현재 99.9%/100%, 100%, 30/30).

알아 둘 점
- 국민연금 자료는 가입자 3인 이상 법인과 10인 이상 개인사업장만 있고, 가입자 수는 60세 이상 등 가입 제외자가 빠져 실제 상시근로자보다 적을 수 있다.
- 업종코드는 국세청 업종코드 체계다. 입력 항목으로 옮기는 표는 `kb/company_map.json` 에 있다.
- 같은 이름의 회사는 사업자번호 4~5번째 자리(법인 본점·지점·개인)와 지역으로 나눈다. 흔한 이름은 후보가 여럿 나오므로 주소·업종을 보고 고른다.
- 상장 여부와 자산총액은 한국거래소·DART 공개 파일로 채운다 (API 키 필요 없음).
- 비상장사는 DART 공시 목록 검색으로 감사보고서 제출(외부감사 대상)과 기업집단현황공시 제출(대기업집단 소속)을 확인한다
  (`engine/dart.py`, 회사를 고를 때 한 번, 30일 보관). DART robots.txt 가 보고서 본문 수집을 막아 비상장사 자산 금액은 가져오지 않는다.
- 'SK하이닉스'처럼 영문 약자로 시작하는 이름은 한글 읽기('에스케이하이닉스')로도 찾는다.
- 인허가는 영업 중인 것만 쓴다. 회사명 줄기가 같고 같은 시·군·구에 있어야 그 회사 것으로 본다 (같은 이름의 회사가 하나뿐이면 지역 무관).
  표준데이터(폐수·소음진동·폐기물)는 자료를 올린 지자체만 있어, 없다고 해서 대상이 아니라는 뜻은 아니다.

## (선택) 유료 AI 웹 조사

`.env` 에 `ANTHROPIC_API_KEY` 를 넣고 `.venv/bin/python server.py` 로 돌리면 화면에 ‘AI로 웹에서 더 조사하기 (유료)’ 버튼이 생긴다.
기본 기능에는 필요 없다.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # 그리고 .env 에 키를 넣는다
```

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `ANTHROPIC_API_KEY` | (없음) | Claude API 키 |
| `REGRADER_MODEL` | `claude-opus-5-5` | 조사·판단에 쓰는 모델 |
| `REGRADER_EFFORT` | `medium` | 생각 깊이 |

비용은 회사 한 곳에 대략 1~2달러로 본다 (실측 전 추정). 같은 입력은 `.cache/ai/` 에 저장해 다시 부르지 않는다.

명령줄로만 돌릴 때:

```bash
python3 -m engine.suggest examples/manufacturer.json   # 결과: out/result.json
```

## 규칙 추가

`kb/rules.json` 에 규칙을 하나 넣는다.

```json
{
  "id": "boiler",
  "when": { "any": ["eq:boiler", "eq:pressure"] },
  "tier": "필수",
  "why": "보일러·압력용기 (검사대상기기 검사, 압력용기 안전검사)",
  "laws": [{ "name": "에너지이용 합리화법", "job": "안전" }],
  "adm": ["검사대상기기", "보일러", "압력용기"],
  "admNames": ["안전검사 고시"]
}
```

- `when`: `always` · `any`(항목 중 하나) · `all`(모두) · `gte`(숫자 이상, 예: `{"employees": 50}`) · `flag`(예: `"listed"`). 적힌 조건은 모두 맞아야 한다.
- `tier`: `필수`(조건이 맞으면 적용) · `확인`(규모·세부 요건에 따라 적용 여부 확인)
- `adm`: 체계도에 연결된 행정규칙 중 이름에 이 낱말이 있으면 추천한다. 앞의 두 낱말은 가중치 2.
- `admNames`: 순위와 상관없이 맨 앞에 넣을 행정규칙 이름

법령의 주요 의무는 `kb/duties.json` 에 넣는다. `art`·`title` 은 현행 조문 번호·제목과 글자까지 같아야 하고, `when` 은 규칙과 같은 조건이다 (`lt` 미만도 쓸 수 있다).

```json
"근로기준법": [
  { "art": "제93조", "title": "취업규칙의 작성ㆍ신고", "text": "취업규칙 작성 후 고용노동부에 신고", "when": { "gte": { "employees": 10 } } }
]
```

새 입력 항목은 `kb/catalog.json` 에 먼저 추가한다. 고친 뒤에는 아래를 돌린다. `verify_kb` 는 법령명·고시명·의무 조문(번호와 제목)이 법제처 현행 법령과 맞는지 검사한다 (법령이 개정되면 다시 돌린다).

```bash
python3 -m unittest discover -s tests
python3 -m engine.verify_kb
```

## 한계 (다음 단계)

- 유해화학물질 영업허가·위험물 제조소·통합허가는 전국 사업장 명단을 받을 수 있는 경로가 아직 없다.
- 주요 의무는 대표 의무만 골랐다. 시행령의 세부 기준(예: 업종별 안전관리자 선임 인원)은 담당자가 확인해야 한다.
- 자치법규(사업장 지역 조례)와 입법예고는 아직 다루지 않는다.
- 규칙은 제조업 위주다. 업종별 규칙과 규모 기준(예: 안전관리자 선임 기준)은 전문가 검토를 거쳐 늘려야 한다.
- 추천 결과는 검토용 후보이며, 최종 적용 여부는 담당자가 판단한다.
